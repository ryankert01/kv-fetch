Lesson 1 · Exact speculative decoding

How the target corrects the draft's guess

A small draft model guesses the next tokens quickly. The large target model checks the guesses. The goal: run faster than the target alone, and still produce text with exactly the target's probabilities.

Greedy decoding: compare the best tokens

You know this case. The target computes its own best token for that position. If it is the same as the draft's token, keep it. If not, use the target's token. It costs nothing extra, because the check already computed it.

Sampling: compare the probabilities

With temperature above 0, both models sample: each token is picked with its probability. "Same token or not" is then a poor test. The good test compares two numbers for the proposed token:

p = the probability the target gives the token.
q = the probability the draft gives it.

The rule

  1. Keep the proposed token with probability p ÷ q (at most 1).
  2. If it is rejected, draw a new token only from the tokens the draft proposes too rarely (p > q). The chance of each is proportional to p − q.

Step 2 is not a fresh draw from the target. A fresh draw would sometimes pick A again and give 39 A and 61 C in the example.

Letters: this page follows Leviathan et al. (p = target, q = draft). Chen et al. swap the two letters. Check which one is the target before you read a formula in a paper.

Why the result is exact

  • A token the draft proposes too often is cut down to the target's rate. A: 60 proposed, 30 kept. The target wants 30.
  • A token the draft proposes too rarely keeps all its proposals. C: 40 proposed, 40 kept. The target wants 70, so 30 are missing.
  • Rejected tries = missing tokens, always (30 = 30 here). So the redraws fill the gap exactly.

This works at any temperature, as long as p and q are the probabilities each model really samples from (after temperature, top-k and top-p). Greedy decoding is the special case where each model puts all its probability on one token.

Two other tests, for comparison. Keeping the draft's token when it equals the target's best token changes the output. Keeping it when it equals a fresh sample from the target is exact, but keeps only 46 of 100 proposals in the example. The rule above keeps 70.

One cycle checks several tokens

Remember

  • Keep a proposal with probability p ÷ q (at most 1). If rejected, redraw from the tokens with p > q, in proportion to p − q.
  • The result has exactly the target's probabilities. The draft changes the speed and which sample you get. Two sampled runs still differ from each other, so compare many samples, never one pair.
  • For one proposal at one position, no exact rule keeps more than this one. A rule that keeps more (example: "keep it if it is in the target's top choices") adds more tokens per cycle but changes the output. Lesson 2 covers these relaxed rules and the length tax.
